5. **文案不自由发挥**：事件、主线、股吧、结局文案全部集中在数据常量里，按设计稿第九节十条样本的味道写；写不到位的留 `TODO:设计补` 占位，不要硬凑。禁止在游戏任何角落出现"经纪业务是指……"这类解释。

## 1. 代码组织

- 区块头注释：`/* ============ 大盘与周期 ============ */`
- 命名沿用银行版风格：短驼峰函数、全大写数据常量。
- **所有数值进 `BALANCE`**，禁止魔数。骨架：

- 事件 schema 沿用银行版：`{id,title,body,opts:()=>[{t,s,fn,disabled?}],cond?,once?,weight?,minMonth?,routes?}`，新增字段只允许 `phase:["mania","crash"]`。不发明新框架。
- 大盘折线：canvas 单次绘制，月结时重画，不进动画循环。

## 2. 对账红线（每期必测）

1. **客户的钱不是公司的钱**：`aum`、`fundHold`、`margin` 任何时候不得流入 `cash`，除非经过收入公式（佣金/尾佣/利息）。
2. 自营：买入不是费用，估值涨跌进当月损益并直接改 `cash`（简化：自营池视为可变现），不重复计。
3. 佣金档位变更当月生效，历史月份不重算。
4. 投行只确认已到里程碑的费用；终止项目不退已收费用，不确认未收费用。
5. 客户资产"净流入"与"估值变动"分开记账，传记与评分只用净流入。
6. 存档任一月读回，续玩到 36 月零报错。
